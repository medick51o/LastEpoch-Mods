## Four scope judgments

1. **The owner's transform alone is not an evidence-backed guarantee.** Installed IL2CPP bindings expose `UITooltipItem.content`, `compareContent`, `blessingContent`, `blessingCompareContent`, and `resonanceContent` on the same instance. They also expose explicit main/comparison implicit, affix-list, and sealed-affix references. See `UITooltipItem.decompiled.txt:2948`, `:3021`, `:3216`, `:3231`, `:3246`, `:3516`, `:3591`; `TooltipItemManager.decompiled.txt:1432` exposes its itemTooltip. These are wrappers, not serialized scene hierarchy or native method-body proof. The collector therefore unions each observed active UITooltipItem transform with its explicit panel transforms, collapses overlapping roots, and validates every active referenced affix anchor belongs to that union. Separate instances are remembered before the existing frame gate; LateUpdate can catch up even when the last observed panel closes. Relayout/Alt/master-off cover observed instances. No common Canvas or manager root is assumed safe, and no new hook is installed.
2. **Sibling coverage is checked at runtime.** Entire subtrees preserve siblings by construction when their common parent is in scope. For standalone ranges the collector requires both the parent and grandparent (the two existing grade-map lookup keys) to lie in the root union. An uncovered ancestor or affix anchor triggers the compatibility fallback instead of a silent loss of colour. Pass 1 also reads saved originals for already composed siblings, so a subsequently rewritten range still gets the grade. Harness cases exercise same-parent and grandparent relationships in detached comparison panels, a later range rewrite, and an external sibling that forces fallback. This is not an assertion that the actual installed prefab has been observed.
3. **Health now tests formatter evidence rather than mere composer ownership.** Only active scoped TMPs count. Actual brackets, including brackets in a marked row's saved original, reset the negative count. Synthesized chips and hidden ranges do not count as success. Scans with native tier text but no brackets count toward one latched warning after 20 such scans; shards, lore, and range-only scopes reset the count. Brackets elsewhere in the scene cannot mask a dead tiered hook on the scoped path. Untiered-only failures are deliberately inconclusive: the allowed files provide no reliable proof that a particular unbracketed unique/implicit row should have passed a successful formatter hook. The warning says “may be dead”; this remains a health heuristic, not a per-hook trace counter. The compatibility scene fallback retains broad observation, so its health evidence is less specific.
4. **Ground labels are independent.** GroundLabels.cs:28 owns its three-ZWSP marker, :41 updates its Alt cache, :73 hooks GroundItemLabel.SetGroundTooltipText, and :84 starts its delayed builder. TerribleTooltipsMod calls that update separately. No path relies on TooltipRecolor's enumeration; the composer already excludes ground-label-marked output. GroundLabels.cs and UnitBorder.cs remain byte-identical to the frozen source hash set. Marker separation is still deferred.

## Fallback and telemetry

A hierarchy exception, uncovered referenced affix, or uncovered range ancestor can request FindObjectsOfType<TextMeshProUGUI>. Attempts are capped at once per 0.5 unscaled seconds, latched before enumeration including throws. Empty valid scopes do not trigger fallback. Failed scope attempts are not relabeled as successful scoped collections. They count in scanErrors; throttled failures can increase scans without increasing scoped/fullScene. This does not change ShouldScan, DirtyFrameWindow, or any MarkDirty call site.

`tmps` counts the TMP entries returned by descendant and scene queries, including inactive descendants and partial scoped work before fallback. It counts each returned TMP once per query, not each later regex/pass visit; a TMP encountered again by fallback counts again because that work actually happened. No profiling clocks or allocations are added by disabled counter calls; only preference guards remain. The fallback reason string is also debug-guarded.

```text
[perf] 5.0s: scans=N (scoped=N, fullScene=N, tmps=N, trigger: dirty=N/markerLoss=N/fallback=N) ruleStart=N ruleReplacement=N ruleAttempts=N ruleMatch=N ruleNoTarget=N ruleGiveUp=N ruleInjected=N ruleReuse=N staleRetired=N scanErrors=N
```

`fallback` inside trigger still means the existing periodic scan gate, not scene search. Healthy runs should show scoped collections, fullScene=0, and TMP totals proportional to the open panels. Positive fullScene/scanErrors and debug reasons expose an unexpected runtime hierarchy; no claim is made that this can never occur. Reducing repeated dirty signals remains a separate ticket.
