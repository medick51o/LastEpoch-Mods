## UnitBorder.cs behaviour
Gate: `Prefs.UnitBorder.Value && Prefs.EnableTooltips.Value && Prefs.Style.Value == SignalStyle.PlainText`. When the gate is false: hide every owned border (SetActive false), do nothing else, zero per-frame work. Master-off or pref-off at runtime → destroy all owned objects, log once `[UnitBorder] off — borders removed`.
**Sprite (once per session, lazily):** `Texture2D` 16×16 RGBA32, filterMode Bilinear, wrapMode Clamp, no mipmaps: fully transparent, then a 1-texel white ring on the outer edge with the four corner texels cleared (a hint of rounding); `Apply()`; `Sprite.Create(tex, new Rect(0,0,16,16), new Vector2(0.5f,0.5f), 100f, 0, SpriteMeshType.FullRect, new Vector4(4,4,4,4))`; keep static references so nothing is collected. If creation throws → `Fail("sprite")`.
**Patch:** `Patch_UpdateLayout` postfix on `UITooltipItem.UpdateLayout` (same signature as TooltipRecolor's), body `try { Run(__instance); } catch (Exception ex) { Fail("UpdateLayout", ex); }`. Idempotent: per tooltip instance id keep a small list of row states keyed by TMP instance id with the text hash last measured.
**Run(tooltip):** find the affix TMPs under the tooltip WITHOUT a scene scan: `tooltip.GetComponentsInChildren<TextMeshProUGUI>(false)` (active only) filtered to those whose `text` ends with the composer's 4-ZWSP marker AND contains `<link="ttu">`. For each: if text hash unchanged and the border exists → only re-sync geometry (cheap, no ForceMeshUpdate); else measure:
1. `tmp.ForceMeshUpdate()` once. Locate the unit: `textInfo.linkInfo` entry whose `GetLinkID()=="ttu"` → `linkTextfirstCharacterIndex`, `linkTextLength`. If linkInfo is empty (NOT PROVEN in this TMP build) fall back to the first K visible characters where K = the plain-text length of the signal computed by stripping tags from the substring between `<link="ttu">` and `</link>`; log once `[UnitBorder] linkInfo empty; using prefix count`.
2. Union `bottomLeft`/`topRight` over the unit's characters with `isVisible`; skip U+200B. Require ≥1 visible char and all on `lineNumber == 0`; else no border on this row (log once per session `[UnitBorder] unit wrapped; row skipped`).
3. Pad: +6 left/right, +2 top/bottom in TMP-local units (not 9: the two spaces after the unit are the only clearance; if the padded right edge would pass the first sentence char's `bottomLeft.x` minus 1, reduce the right pad to fit). Never change `tmp.margin`.
4. Transform the four corners with `tmp.rectTransform.TransformPoint` → `parent.InverseTransformPoint`; border RectTransform: parent = `tmp.transform.parent`, anchors (0,1)/(0,1), pivot (0,1), `anchoredPosition` = top-left in parent local, `sizeDelta` = size; sibling index = `tmp.transform.GetSiblingIndex()` (before Text); `localScale` one.
5. Border object (create once per row state, name `TT_UnitBorder`): `new GameObject` + `RectTransform` + `CanvasRenderer` + `Image` (`sprite` = ours, `type = Sliced`, `fillCenter = false` if available else keep the transparent centre, `raycastTarget = false`, `material` = default) + `LayoutElement { ignoreLayout = true }`. Colour: Neutral → `#5A4670` alpha 1; TierColor → `Colors.TierColor(tier)` at alpha 0.6 (tier parsed from the unit text: `Tier\s*(\d)` or `T(\d)`; if none, Neutral).
6. Log ONCE per tooltip generation: `[UnitBorder] placed n/m rows path=runtime-9slice` (n placed, m candidate rows). Nothing else at Msg level except the once-per-session lines above (DebugLog-gated details are welcome).
**OnLateUpdate:** only while any border exists: for each row state, if the TMP is destroyed/inactive or its text no longer carries the marker+link → hide the border (SetActive false), keep the state for reuse; if the tooltip root is destroyed → drop the state. No ForceMeshUpdate, no scans, no allocation in the common case.
**Fail(stage, ex):** one line `[UnitBorder] OFF (<stage>: <type>: <message>) — plain coloured text`, destroy owned objects, latch off for the session. The game's UpdateLayout must always return normally (the postfix try/catch).
Comparison tooltips: rows are found per tooltip instance, so two tooltips get independent borders; never share an Image.
