# Last Epoch zone and boss context research

Accessed 2026-10-02. Read-only inspection of the installed `Il2CppLE.dll` and official Last Epoch forum/patch-note pages. Game install metadata identifies itself only by local DLL path; no version/season stamp was established here. Treat mechanics as patch-sensitive, especially Season 5.

## What the game exposes for death context

- `Il2Cpp.PlayerActorSync::ReceiveDetailedDeathInfo(Il2Cpp.DamageType, Il2CppSystem.Nullable\`1<Il2Cpp.DamageType>, System.Boolean, System.Int32, System.Int32, Il2Cpp.Ailment, Il2Cpp.Ability, Il2Cpp.ActorSync, Il2Cpp.IrregularDamageSourceID, System.Boolean isBossfight)` is present. The final bool is an explicit boss-fight signal (high confidence for “death occurred during a game-classified boss fight”). This is the strongest supported gate for boss tips. It does not identify the boss by itself.
- The matching local UI method is `Il2Cpp.DeathInformationText::UpdateDeathInfo(DamageType, Nullable<DamageType>, Boolean, Int32, Int32, Ailment, Ability, ActorSync, IrregularDamageSourceID)` (9 parameters, no boss flag). Its text composer is `ComposeLocalizedDeathInfo` with the same 9 parameters. In the current hook, only the network callback can populate `IsBossFight`; the local UI callback cannot. Avoid assuming `args[9]` exists on `UpdateDeathInfo`.
- `Il2Cpp.DeathInformationText::GetLocalizedAttackerName(Il2Cpp.ActorSync)` supplies a localized attacker string; use it as a candidate label alongside `isBossfight`, not a stable boss identifier. The attacker can be an add, proxy or environmental actor. Preserve the death’s localized ability, damage element(s), and attacker text with the flag.
- Current `PlayerProbe.Zone()` returns `UnityEngine.SceneManagement.SceneManager.GetActiveScene().name` after `Refl.CleanName`. This is a scene/internal name, not verified localized zone text and may identify a shared arena or transition scene. `Il2Cpp.ZoneInfoManager::get_ZoneLevel()` is present for level context. `Il2Cpp.SceneNameTMP` has a `tmp` TextMeshPro field and scene-change handling, but this inspection did not establish a stable scene-to-localized-area API.
- `Il2Cpp.ActorSync::get_actorData()` is present if a future probe needs the attacker’s actor data. No stable boss ID or encounter ID was found in the inspected metadata. The empty-looking `ZoneInformation` component exposes no useful public methods/properties in this metadata dump.

**Implementation confidence:** explicit flag is high confidence for a broad boss encounter menu and linking an individual death to “boss fight.” Exact boss attribution by name/scene alone is medium-to-low; require both the flag and a known localized attacker match, and otherwise show generic boss help. Never classify a boss just because the scene name resembles an arena.

## Matching guidance

1. Only link a death to boss tips when `ReceiveDetailedDeathInfo` reports `isBossfight == true`; the local 9-argument hook cannot supply this flag.
2. Match the localized attacker label against a small explicit alias set. Keep campaign/timeline/dungeon/Harbinger variants separate when their names differ. If the actor resolves to an add or no exact alias matches, offer generic encounter tips without naming a boss.
3. Record `SceneManager.GetActiveScene().name` and `ZoneInfoManager.ZoneLevel` as context fields. Do not promote a raw scene identifier to a player-facing area name without checking its localized UI text in game.
4. Leave element fields as death-specific measured data from `DamageType` / nullable secondary type. The advice cards should summarize known encounter hazards and clearly state when that hazard typing is community-reported or not yet verified.

## Additional structured game-data results

A parallel read-only lookup of Tunklab’s published game data adds stronger encounter placement and one explicit damage-type set:

- **Emperor of Corpses:** Reign of Dragons timeline boss (level 85), quest zone The Rotting Hoard. Data also lists Slaughtered Thrall as a summon at that zone. Current public NPC data does not expose verified ability names or damage types. [Timeline data](https://lastepoch.tunklab.com/timeline/reign_of_dragons), [NPC data](https://lastepoch.tunklab.com/npc/UndeadDragonVolatileZombie).
- **Heorot:** The Age of Winter timeline boss (level 90). The accessible NPC entry does not provide verified attack or damage data. [Timeline data](https://lastepoch.tunklab.com/timelines), [NPC data](https://lastepoch.tunklab.com/npc/Heorot).
- **Chronomancer Julra:** Temporal Sanctum data explicitly lists Void, Cold, and Lightning damage types and identifies Temporal Shift between Divine and Ruined eras. Tip can say: “Use Temporal Shift to move between eras and avoid hazards; prepare for Void, Cold, and Lightning.” The defensive recommendation is an inference from the listed damage types. [Dungeon data](https://lastepoch.tunklab.com/dungeon/temporal_sanctum). Official 0.8.4 announcement independently confirms the dungeon and era-shift mechanic: [EHG announcement / notes](https://www.lastepochtools.com/news/article/eternal-legends-beta-0-8-4-patch-notes-45588).

Tunklab is structured game data, but not the developer’s official site. Treat its fields as datamined-derived reference and version-sensitive. I did not find enough data in the requested primary sources to publish attack-by-attack damage typing for Emperor or Heorot, or detailed Julra attack names. The tips above intentionally stay broad where data is incomplete.
