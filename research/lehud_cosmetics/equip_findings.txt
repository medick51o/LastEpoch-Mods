COSMETIC EQUIP ANALYSIS — WHY ONLINE EQUIP FAILS
===================================================
Date: 2026-04-16
Sources: Il2CppLE.dll (game), LastEpoch_Hud.dll (decompiled), medick_4_skins.dll

1. WHAT LE_HUD PATCHES (AND DOESN'T)
-------------------------------------
LE_hud has EXACTLY ONE cosmetic Harmony patch:
  - CosmeticsManager.GetOwnedCosmetics()  [HarmonyPrefix, return false]

It does NOT patch any equip, send, or network methods. Full HarmonyPatch
scan of decompiled LE_hud (34k lines) confirms this — no patches on
SendSelectCosmetic, TryEquipItem, ClientCosmeticsNetworkManager, or any
MessageTryEquipCosmetic handler. medick_4_skins is identical — same
single GetOwnedCosmetics patch.

2. THE ONLINE EQUIP FLOW (FROM Il2CppLE.dll)
---------------------------------------------
When you click "equip" on a cosmetic, the game does:

  UI click -> HandleCosmeticItemClicked -> SendSelectCosmetic
  -> MessageTryEquipCosmetic (sent to server)
  -> Server validates ownership via PlayFab inventory
  -> Server responds with EITHER:
     MessagePlayerEquippedCosmetic  (success)
     MessageEquipCosmeticFailed     (failure)

Key classes in LE.Networking.Cosmetics:
  ClientCosmeticsNetworkManager  — sends/receives all cosmetic messages
  PlayFabCosmeticsClient         — actual PlayFab backend calls

Key network messages:
  MessageTryEquipCosmetic          — client -> server "I want to equip X"
  MessageTryUnequipCosmetic        — client -> server "I want to unequip X"
  MessagePlayerEquippedCosmetic    — server -> client "equip confirmed"
  MessagePlayerUnequippedCosmetic  — server -> client "unequip confirmed"
  MessageEquipCosmeticFailed       — server -> client "denied"
  MessageUpdateCosmetics           — server -> client "here's your state"
  MessageClearCosmetics            — server -> client "reset"
  MessageUpdateCosmeticsFromClient — client -> server "sync my state"

3. WHY IT WORKS OFFLINE BUT NOT ONLINE
---------------------------------------
OFFLINE: GetOwnedCosmetics returns all IDs. The game calls
SelectOfflineCosmetic, which writes to local save files
(OfflineEquipsCosmeticsFileName, OfflineOwnedCosmeticsFileName).
No server validation. Works perfectly.

ONLINE: GetOwnedCosmetics returns all IDs (UI shows everything as owned).
But when you click equip, SendSelectCosmetic sends
MessageTryEquipCosmetic to the server. The server checks its OWN
database (PlayFab). You don't own it there. Server responds with
MessageEquipCosmeticFailed. The client calls HandleEquipCosmeticFailed.

4. WHAT WOULD NEED TO BE PATCHED
---------------------------------
Option A: Intercept SendSelectCosmetic — make it call the OFFLINE
equip path (SelectOfflineCosmetic) instead of sending to server.
Then patch GetLocalPlayerEquippedCosmetics to read from offline save.

Option B: Patch HandleEquipCosmeticFailed to suppress the failure
and force-apply the cosmetic locally via
EquipmentVisualsManager.CosmeticAdded + manual cache update.

Option C: Patch ClientCosmeticsNetworkManager to intercept the
TryEquipCosmetic message, never send it, and fake the
MessagePlayerEquippedCosmetic response locally.

5. IS THIS SAFE?
-----------------
NO — this is fundamentally different from the ownership patch.

The ownership patch (GetOwnedCosmetics) PREVENTS a server call.
The server never learns anything. Completely silent.

Equip interception would require one of:
  a) Suppressing a message the server expects (detectable)
  b) Faking server responses locally (desyncs server state)
  c) Writing to offline files while online (game may override)

Risk: The server tracks equipped cosmetics per-character. If you
force-equip locally, the server's state and client's state diverge.
Next session or zone change, server pushes its state via
MessageUpdateCosmetics, overwriting your local equips.

The cosmetic IS visual-only on OTHER players' screens (they see your
server-state cosmetics, not your local state). But on YOUR screen,
a forced local equip would show the skin until a server sync event.

6. BOTTOM LINE
--------------
Ownership patch = safe, silent, server never knows.
Equip patch = risky, detectable, temporary (server overwrites on sync).

The ownership-only approach already works perfectly OFFLINE.
For ONLINE, the server is the gatekeeper. No client-side patch can
permanently bypass server-validated equip without the server eventually
correcting it.
